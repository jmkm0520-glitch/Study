# 데이터 정책 및 분석 설계

## 1-5. 중복 판단 기준

### 결정

중복 여부는 **원문 URL**을 기본 기준으로 판단한다.

```text
같은 원문 URL = 같은 자료
```

원문 URL이 없는 자료는 정상 자료로 저장하지 않고 정제 단계의 오류 대상으로 처리한다. 따라서 제목만 같다는 이유로 중복 처리하지 않는다.

### URL을 선택한 이유

- 보건복지부 RSS의 각 보도자료에 고유한 원문 링크가 있다.
- 제목은 수정되거나 서로 다른 자료에서 같을 수 있다.
- 작성일도 하루에 여러 자료가 올라오므로 단독 기준으로 사용할 수 없다.
- URL은 사람이 원문을 확인할 때도 반드시 필요한 필드다.
- SQLite의 `UNIQUE` 제약조건으로 중복 저장을 막기 쉽다.

### URL 정규화

비교하기 전에 다음과 같이 URL을 정리한다.

- 앞뒤 공백 제거
- HTML의 `&amp;`를 `&`로 변환
- URL 조각을 나타내는 `#...` 제거
- 호스트 이름을 소문자로 통일

쿼리 문자열은 보건복지부 문서 ID를 포함하므로 임의로 제거하거나 순서를 바꾸지 않는다.

### 데이터베이스 규칙

`documents.url` 컬럼에 `UNIQUE NOT NULL` 조건을 적용한다. 프로그램의 중복 검사와 데이터베이스 제약조건을 함께 사용하여 실수로 같은 자료가 두 번 저장되는 것을 막는다.

## 1-6. 중복 처리 정책

### 결정

첫 버전에서는 **skip** 정책을 사용한다.

```text
이미 저장된 URL이면 새로 저장하지 않고 건너뛴다.
```

### skip을 선택한 이유

- 같은 RSS를 여러 번 수집해도 데이터가 늘어나지 않는다.
- 기존에 완료된 AI 요약과 분류 결과가 덮어써지지 않는다.
- 동작이 단순하여 첫 구현과 테스트가 쉽다.
- 원본 수집 기록과 정제 데이터의 관계를 이해하기 쉽다.

### 처리 흐름

1. RSS 항목의 URL을 정규화한다.
2. SQLite에서 같은 URL이 있는지 확인한다.
3. 없으면 새 자료로 저장한다.
4. 있으면 저장하지 않고 중복 건수를 증가시킨다.
5. `[WARNING] 중복 데이터 N건 스킵` 로그를 남긴다.

### 한계와 향후 개선

기관이 같은 URL의 본문을 수정해도 첫 버전에서는 기존 정제 데이터가 바뀌지 않는다. 수정본 반영이 필요해지면 본문 해시와 수정 시각을 추가하고 `upsert` 정책으로 확장한다.

## 1-7. 업무 분야 목록

### 결정

자료는 다음 8개 분야 중 **하나 이상**으로 분류한다.

| 분야 | 판단 기준 | 예시 |
|---|---|---|
| 고용 | 채용, 일자리, 근로, 고용지원, 노동시장 | 취업 지원, 인력 확충 |
| 청년 | 청년 대상 정책, 지원, 참여, 생활 | 청년 지원사업, 청년 간담회 |
| 복지 | 돌봄, 취약계층, 사회보장, 연금, 복지서비스 | 통합돌봄, 장애인 지원 |
| 교육 | 학교, 대학, 학습, 훈련, 인재 양성 | 직무교육, 전문인력 양성 |
| AI | 인공지능 기술, 정책, 도입, 활용, 규제 | 공공 AI, 의료 AI |
| 산업 | 기업, 시장, 연구개발, 투자, 산업 육성 | 바이오산업, 기업 지원 |
| 디지털 | 정보통신, 데이터, 플랫폼, 디지털 전환 | 디지털 헬스케어, 전산 시스템 |
| 기타 | 위 7개 분야에 명확히 해당하지 않음 | 일반 행사 또는 기관 소식 |

### 분류 규칙

- 한 자료가 여러 분야에 해당하면 복수 분야를 허용한다.
- 최소 한 개의 분야를 반드시 저장한다.
- 허용 목록에 없는 AI 응답은 저장하지 않는다.
- 어떤 분야에도 명확히 해당하지 않으면 `기타`를 저장한다.
- `기타`와 다른 분야는 동시에 저장하지 않는다.
- 분야는 제목만 보지 않고 제목과 본문을 함께 판단한다.

## 1-8. 중요도 판단 기준

### 기본 원칙

중요도는 글의 감정, 길이, 유명도와 관계없이 **업무에 미치는 영향과 대응 시급성**으로 판단한다.

### HIGH

다음 중 하나 이상에 해당하면 HIGH 후보로 판단한다.

- 법령, 제도, 정책 또는 지원 조건이 변경됨
- 신청, 제출, 시행 등 명확한 기한이 있고 대응이 필요함
- 지원 대상, 자격, 금액 또는 절차가 변경됨
- 현재 업무 방식이나 의사결정에 직접 영향을 줌
- 즉시 확인하거나 후속 조치를 해야 하는 공고임

AI는 HIGH로 판단한 구체적인 원문 근거를 함께 반환해야 한다. 근거가 원문에 없으면 HIGH로 저장하지 않는다.

### MEDIUM

다음과 같이 당장 대응할 필요는 없지만 향후 업무에 영향을 줄 수 있으면 MEDIUM으로 판단한다.

- 향후 시행될 정책 방향이나 제도 변화가 발표됨
- 관련 산업, 기술 또는 시장의 의미 있는 동향임
- 업무 계획에 참고할 연구, 협의 또는 추진 계획임
- 아직 세부 조건이나 일정이 확정되지 않음

### LOW

다음처럼 참고 목적이며 직접적인 업무 영향이 낮으면 LOW로 판단한다.

- 일반 행사, 캠페인 또는 홍보성 소식
- 이미 종료된 활동의 단순 결과 소개
- 정책이나 업무 변경이 없는 일반 정보
- 현재 담당 업무와 연결되는 구체적 영향이 없음

### 경계 상황 처리

- 판단 근거가 부족하면 더 높은 중요도를 추측하지 않는다.
- HIGH와 MEDIUM 사이에서 불확실하면 MEDIUM으로 분류하고 `확인 필요`에 이유를 기록한다.
- MEDIUM과 LOW 사이에서 불확실하면 LOW로 분류하고 판단 근거를 기록한다.
- 허용 값은 `HIGH`, `MEDIUM`, `LOW` 세 개뿐이다.

## 1-9. 기본 트렌드 분석 항목

첫 버전에서는 다음 **3개**를 구현한다. 과제의 최소 조건은 2개지만, 모두 규칙 기반으로 계산할 수 있어 결과를 검증하기 쉽다.

### 1. 분야별 자료 수

선택 기간 동안 각 분야에 속한 자료의 수를 계산한다.

```text
복지: 12건
청년: 7건
AI: 5건
```

목적은 어떤 업무 분야의 발표가 많았는지 빠르게 확인하는 것이다. 복수 분야 자료는 해당되는 각 분야에 한 번씩 집계한다.

### 2. 주요 키워드 TOP N

선택 기간의 제목과 정제된 본문에서 자주 등장한 핵심 단어를 계산한다.

- 조사, 접속사처럼 의미가 약한 불용어 제외
- 기관명처럼 모든 글에 반복되는 일반 단어 제외
- 같은 단어의 단순 표기 차이는 가능한 범위에서 통합
- 기본 출력 개수는 TOP 5
- 사용자가 지정하면 TOP N으로 변경 가능

목적은 여러 자료에서 반복되는 주제를 찾는 것이다.

### 3. 중요도별 자료 분포

선택 기간의 HIGH, MEDIUM, LOW 자료 수와 비율을 계산한다.

```text
HIGH: 3건 (15%)
MEDIUM: 9건 (45%)
LOW: 8건 (40%)
```

목적은 즉시 확인해야 할 자료가 얼마나 있는지 파악하는 것이다.

### 공통 분석 조건

- `--date-from`과 `--date-to` 기간을 적용한다.
- 분석 대상이 없으면 `분석할 데이터가 없습니다.`라고 안내한다.
- AI가 아닌 SQLite의 저장 데이터를 기준으로 건수를 계산한다.
- 집계에 사용한 전체 자료 수와 분석 기간을 함께 표시한다.
- 결과는 CLI 화면과 Markdown 브리핑에서 재사용한다.

### 향후 확장 후보

- 기간별 자료 증가·감소
- 반복 등장 이슈 묶기
- 주요 정책 변화 탐지
- AI 기반 종합 트렌드 요약

이 항목들은 첫 버전의 세 가지 기본 분석을 완성한 후 추가한다.
